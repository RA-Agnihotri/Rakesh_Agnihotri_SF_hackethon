1. Solution Overview

The Insurance AI Hub is an enterprise intelligence platform built entirely on Snowflake, transforming insurance data into conversational, governed, and actionable insights. Users ask natural-language questions — via text or voice in any language — and receive grounded answers backed by source citations, with the ability to take action through Jira.

2. Snowflake Feature Integration Map

Every capability in the platform maps directly to a native Snowflake feature. No external ML frameworks, no third-party AI APIs, no external databases.

#Snowflake FeatureHow We Use ItCategory
1Cortex Agent5 agents with multi-tool orchestration (up to 7 tools per agent). Each agent routes user questions to the right Semantic View, Search service, chart tool, or MCP action.Cortex AI
2Cortex AnalystNL-to-SQL via 5 Semantic Views. The agent calls Cortex Analyst, which matches user questions against Verified Queries or generates SQL from the semantic model.Cortex AI

4AI_TRANSLATEMultilingual voice input pipeline. User speaks in any language → browser transcribes → AI_TRANSLATE(?, '', 'en') auto-detects and translates to English → agent processes. Parameterized bindings prevent SQL injection.Cortex AI

7Verified Queries (VQRs)25+ curated SQL templates that Cortex Analyst uses as golden queries for common business questions, improving accuracy and consistency.Semantic Layer
8MCP ConnectorsAtlassian MCP server (Jira + Confluence) using Dynamic Client Registration OAuth. Agents create/search Jira tickets from insights. Per-user authentication.Platform
9Snowflake Intelligence (CoWork)Account-level Intelligence object with all 5 agents registered. Business users access agents through CoWork without the React dashboard.Platform
10Streams (CDC)3 append-only streams: CLAIMS_STREAM (fraud monitoring), DQ_RESULTS_STREAM (failure alerting), DOCUMENT_CHUNKS_STREAM (search freshness tracking).Automation
11Tasks (scheduled + triggered)3 tasks: daily DQ score refresh (CRON 6 AM UTC), stream-triggered fraud flagging (fraud_score > 0.7), stream-triggered DQ failure alerting. Task DAG with parent-child dependency.Automation
12AlertsDQ score drop monitor: every 12 hours, alerts if any table's quality score drops below 70%. Writes to AGENT_AUDIT_LOG for traceability.Automation
13Object TagsPII_LEVEL (HIGH/MEDIUM/LOW/NONE) on columns, BUSINESS_DOMAIN (7 values) on tables. Applied at CREATE TABLE time for catalog-level governance.Governance
14Dynamic Masking Policies3 policies: MASK_EMAIL (partial redaction), MASK_PHONE (full redaction), MASK_ADDRESS (full redaction). Uses IS_DATABASE_ROLE_IN_SESSION — admin sees real data, everyone else sees masked.Governance
15Database Roles6-role hierarchy: ADMIN → DATA_STEWARD, EXEC → ANALYST, UW → ANALYST, CLAIMS → ANALYST. Separate DEPLOY_ROLE (DDL) and SERVICE_ROLE (runtime) at account level.Governance
16Resource Monitor500 credits/month on COMPUTE_WH. Triggers: notify at 75%, notify at 90%, suspend at 100%.Cost Control
17Budget1,000 credits/month covering warehouse + serverless AI (Cortex inference, Search, tasks). Caps all credit types, not just warehouse.Cost Control
18Query AccelerationEnabled on COMPUTE_WH for ad-hoc analytical queries from dashboard and agents.Performance
19Vector EmbeddingsVECTOR(FLOAT, 768) column on DOCUMENT_CHUNKS for semantic similarity search via Cortex Search.Data

6. Governance & Security

Access Control (RBAC)

  • INSURANCE_ADMIN_ROLE — Full access + masking bypass
  • INSURANCE_EXEC_ROLE — Agents + MCP + analytics read
  • INSURANCE_UW_ROLE — Pricing + matching agents
  • INSURANCE_CLAIMS_ROLE — Analytics + documents
  • INSURANCE_DATA_STEWARD_ROLE — Data quality schema
  • INSURANCE_ANALYST_ROLE — Base analytics read
  • Separate DEPLOY_ROLE (DDL) and SERVICE_ROLE (runtime)

Data Protection

  • PII_LEVEL tag — HIGH (email, phone, address), MEDIUM (DOB)
  • BUSINESS_DOMAIN tag — 7 domains for catalog classification
  • MASK_EMAIL — jo***@email.com for non-admin
  • MASK_PHONE — ***-**** for non-admin
  • MASK_ADDRESS — *** REDACTED *** for non-admin
  • Resource Monitor — 500 credits/month, auto-suspend
  • Budget — 1,000 credits/month (warehouse + serverless AI)

8. Multilingual Voice Pipeline

User speaks Web Speech API AI_TRANSLATE Cortex Agent (any language) ──► speech-to-text ──► SELECT AI_TRANSLATE ──► processes (client-side, (?, '', 'en') English query no Snowflake (parameterized, with citations compute) auto-detect source) Supported: 30+ languages | 7 dashboard pages | SQL-injection safe
Security: User voice text is sent as a bind parameter (?) to AI_TRANSLATE — it never touches the SQL string. The executeSQLWithBindings() function sends values out-of-band via the Snowflake SQL API bindings mechanism.
